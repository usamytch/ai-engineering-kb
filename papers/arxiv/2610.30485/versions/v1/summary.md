# Why Bother Me Again? Benchmarking Personal Agent Memory for Interaction Preferences

## Executive summary

MemPABench is a long-horizon, on-policy benchmark for whether personal-agent memory learns interaction preferences, preserves their context, updates them, and turns them into behavior. Its strongest controlled finding is that File memory improves preference selection over No Memory, whereas three retrieval systems do not. That gain is qualified: File memory tracks changes better but transfers preferences across contexts, and even Oracle-supplied preferences do not reliably override default model habits. The benchmark is unusually instrumented, but external validity is constrained by four television-derived simulated users, LLM simulators and judges, authored worlds, and partly reviewer-assigned preference labels.

## Problem

**Statement.** The paper studies whether a persistent personal agent can infer how a user wants assistance delivered, choose the current preference for the correct work or personal context, revise it after change, and realize it in the interaction rather than merely recall user facts.

**Why it matters.** A task can be completed correctly while repeated questions, unnecessary approvals, excessive explanation, or unwanted outreach impose recurring interaction burden. Such failures matter because interaction preferences can vary by context and change after consequences.

**Scope.** The study covers four anonymized, persona-grounded simulated users; work and personal contexts; fourteen interaction attributes; four memory systems; four language-model backbones; persistent executable worlds; and controlled preference-change events.

## Method

MemPABench models a preference as state indexed by user, context, attribute, and time. Each evaluated agent accumulates its own history through live sessions in an executable world. At isolated checkpoints, probes measure exact preference selection, discrimination between contexts, tracking before and after changes, delivered behavior, and simulated-user perception. A wrapper makes the selected interaction setting explicit and applies it without access to the target. No Memory and Oracle isolate default-policy and downstream realization failures.

### Key components

- A four-month timeline per user with accumulation sessions and fixed change events; each session targets one context–attribute cell.
- Fourteen attributes grouped into Expression Style, Disclosure, Initiative & Autonomy, and Information Flow, with discrete observable settings.
- A persistent world accessed through executable tools; completed writes affect later sessions, while probes branch from frozen checkpoints and are discarded.
- A simulated user that exposes preferences through reactions rather than naming settings, plus runtime leakage controls and post-hoc auditing.
- Four memory conditions: consolidated File memory, raw-message Simple RAG, Mem0 extraction and search, and MemOS textual memory.
- Three-stage diagnosis: acquisition into memory, selection of a setting, and behavioral realization after selection.

### Assumptions

- Television-character transcripts and author review provide defensible proxies for individual interaction preferences.
- Anonymized persona simulations retain relevant behavior while removing recognizable-character shortcuts.
- User reactions generated from preference skills are learnable evidence comparable enough to human feedback for benchmarking.
- The explicit interaction-tool choice and wrapper faithfully operationalize preferences that ordinary agent runtimes cannot directly control.
- LLM-judge scores and simulated-user ratings adequately represent realization quality within this environment.

## Main claims

- **The benchmark contributes an on-policy evaluation in which each agent’s own actions and the resulting user reactions create its history, rather than supplying a fixed conversation history.**
  - Evidence: [b00009-af0577072a] “Each PA is evaluated on a history generated by its own actions and the resulting user responses.”
- **The formulation distinguishes acquiring preference evidence, selecting the current setting, and realizing that setting in delivered behavior, enabling stage-specific diagnosis.**
  - Evidence: [b00033-0d3f86f566] “Equations (1) and (2) separate three stages at which a PA can fail.”; [b00033-0d3f86f566] “In acquisition, 𝒜 must turn the user’s reactions into preference knowledge in Mt”; [b00033-0d3f86f566] “In realization, yt must follow that setting, which BRS and PRS score”
- **The experimental interface holds users, sessions, tools, and wrapper constant across memory systems while allowing condition-specific histories and memory states.**
  - Evidence: [b00379-24b3e61328] “all conditions share the same users, session schedule, wrapper, tools, checkpoint timepoints, and probe protocol.”; [b00379-24b3e61328] “Their accumulated histories and memory states remain condition-specific.”
- **The authors report strong internal checks for whether reactions expose preferences and for whether simulator messages leak them directly.**
  - Evidence: [b00441-532b5cdd92] “The preference was conveyed in 99.3% of the sessions, with an inter-annotator agreement of 95.4%”; [b00362-d6809805df] “The audit found no leakage.”

## Results

- **File memory is the only tested memory condition with a clear aggregate PSA improvement: it reaches 59.2% versus 49.6% for No Memory, a gain of 9.6 points with a 95% interval of [+3.9, +15.6]. Retrieval-based systems remain essentially level with No Memory.**
  - Context: This is the strongest controlled comparison. The interval is cluster-bootstrapped, but it establishes performance only inside the benchmark’s simulated population and protocol.
  - Evidence: [b00090-3d6511f98b] “No Memory, where the PA selects by its defaults, reaches 49.6%”; [b00090-3d6511f98b] “It raises PSA to 59.2%, a mean gain of 9.6 points over No Memory (95% cluster-bootstrap interval [+3.9, +15.6]).”; [b00090-3d6511f98b] “Mem0, MemOS, and Simple RAG stay at the level of No Memory, with PSA of 50.0%, 50.0%, and 49.9%.”
- **The diagnostic sample indicates a retrieval bottleneck: applicable interaction preferences occur in only 7 of 334 judged retrieval-condition inputs, compared with 60 of 111 (54%) File-memory inputs. A focused two-probe case study found the preferences stored but not retrieved by any retrieval system.**
  - Context: The broad input audit supports poor retrieval incidence; the storage-versus-retrieval attribution is narrower because it comes from selected cases for one user.
  - Evidence: [b00096-ee599f8d4d] “It appears in only 7 of the 334 judged probes, compared with 60 of 111 (54%) under File memory.”; [b00098-6359781118] “the preference had been written to each store, yet none of the three conditions retrieves it before the PA’s selection”; [b00098-6359781118] “The bottleneck in both cases is retrieval, not storage.”
- **File memory improves temporal tracking but harms contextual isolation: PET is 25.4% versus 11.2% for No Memory, while CS is 14.4% versus 21.8%. In 26.9% of File-memory CS pairs, a target setting from one context carries into the other.**
  - Context: This is a consequential trade-off: retaining preferences does not imply retaining their scope. The reported CS difference does not establish improvement and trends in the wrong direction.
  - Evidence: [b00108-8a9502cab2] “Its PET is 25.4%, more than twice the 11.2% of No Memory”; [b00108-8a9502cab2] “the CS does not improve, at 14.4% against 21.8%”; [b00108-8a9502cab2] “In 26.9% of its CS pairs, the PA carries the target setting of one context over to the other.”
- **Correct preference availability does not ensure compliant behavior. Under Oracle, five difficult settings pass at 60% versus 95% for the other 25 settings; moving from No Memory to Oracle raises correct selection from 33% to 96%, but replies meeting BRS of 4 or higher rise only from 24% to 59%.**
  - Context: This separates memory failure from policy and realization failure. It suggests that better retrieval alone cannot solve habitual over-explanation or acting on assumed missing facts.
  - Evidence: [b00113-f7de8c3469] “their correctly selected probes pass in only 60% of cases, against 95% for the other 25 settings.”; [b00113-f7de8c3469] “Oracle raises correct selections of the five settings from 33% to 96%”; [b00113-f7de8c3469] “the share of replies with a BRS of 4 or higher rises only from 24% to 59%.”

## Experimental evaluation

### Datasets

- MemPABench: four anonymized persona-grounded users, each with work and personal settings for fourteen attributes, embedded in persistent four-month executable worlds.
  - Evidence: [b00027-156fde78ed] “With two contexts, work and personal, and 14 attributes, each user has 28 context–attribute cells”; [b00045-80dcda787c] “Each user u lives in a world with a storyline that covers four months”
- Each user timeline contains 99 sessions: 94 live accumulation sessions and five controlled preference-change events.
  - Evidence: [b00049-694ce31ae8] “Each user’s timeline consists of 99 sessions over the four months: 94 accumulation sessions”; [b00049-694ce31ae8] “and five controlled preference-change events.”

### Baselines

- No Memory removes accumulation memory and measures backbone defaults; Oracle supplies the target setting and definition at each probe.
  - Evidence: [b00077-ab7ed01774] “No Memory skips accumulation and gives the PA no memory”; [b00077-ab7ed01774] “Oracle replaces the evidence Et at each probe with the target setting pu,c,a(t) and its definition”
- Compared memory systems are File memory, Simple RAG, Mem0, and MemOS.
  - Evidence: [b00083-38a5e564de] “We evaluate four systems.”; [b00083-38a5e564de] “❶ File memory”; [b00083-38a5e564de] “❷ Simple RAG”; [b00083-38a5e564de] “❸ Mem0 v2.0.2”; [b00083-38a5e564de] “❹ MemOS v2.0.15”

### Metrics

- PSA: exact-match accuracy on final-probe target settings.
  - Evidence: [b00063-d6227b052d] “Preference Selection Accuracy (PSA) is the fraction of final probes in which the PA correctly selects the target setting”
- CS: joint correctness for attributes whose work and personal targets differ.
  - Evidence: [b00066-8c801d1ec5] “A pair scores 1 only when the PA selects the target setting in both contexts”
- PET: joint correctness before and after a controlled preference change.
  - Evidence: [b00069-8fc8d30259] “A cell scores 1 only when the PA selects the target setting both before and after its change”
- BRS and PRS score behavioral realization and simulated-user perception on a 1-to-5 scale.
  - Evidence: [b00073-f921490580] “gives a Behavioral Realization Score (BRS) from 1 to 5.”; [b00075-47ce9c6990] “rates from 1 to 5 how well the PA met the user’s preference”

### Ablations

- Oracle removes acquisition and retrieval uncertainty, isolating selection-following and realization failures.
  - Evidence: [b00077-ab7ed01774] “which removes acquisition from the pipeline.”
- No Memory isolates each backbone’s default interaction tendencies.
  - Evidence: [b00077-ab7ed01774] “its selections and delivered interactions reflect the backbone’s default tendencies.”
- The anonymization shortcut check compares source identity, anonymized profile, and no-information prompts.
  - Evidence: [b00275-e050605401] “there are three conditions. ❶ Source identity.”; [b00275-e050605401] “❷ Anonymized profile.”; [b00275-e050605401] “❸ No information.”

### Negative results

- Mem0, MemOS, and Simple RAG do not improve aggregate PSA beyond No Memory.
  - Evidence: [b00090-3d6511f98b] “Mem0, MemOS, and Simple RAG stay at the level of No Memory”
- All tested memory conditions have low CS and PET; retrieval systems remain near No Memory on both.
  - Evidence: [b00105-725f46417f] “CS and PET stay low under every memory condition”; [b00105-725f46417f] “Mem0, MemOS, and Simple RAG stay at the level of No Memory”
- Information Flow is the hardest dimension under every condition, showing that action-related preferences remain difficult.
  - Evidence: [b00111-44485a77c0] “Information Flow is the hardest under every condition”; [b00111-44485a77c0] “Its PSA stays at 34–44%, the lowest of the four”


## Limitations

- External validity is narrow: all users are simulated and grounded in four television personas rather than recruited personal-agent users. Rich characterization improves consistency but cannot establish transfer to real preference expression, ambiguity, or behavioral change.
  - Evidence: [b00040-ea794c345f] “drawing four users from The Big Bang Theory and the U.S. The Office”; [b00053-1061ef424e] “A separate nanobot agent plays user Uu from the anonymized profile”
- Ground-truth preferences contain substantial judgment: only part of the matrix was confirmed at high confidence, while remaining cells underwent review or manual assignment. This can embed author interpretations into targets.
  - Evidence: [b00262-3d36fbf203] “Of the 112 cells, 53 high-confidence settings were confirmed by this check, and the other 59 went through review.”; [b00262-3d36fbf203] “In 23 reviewed cells we chose the setting ourselves”
- The same model family instance gives both realization scores, creating correlated measurement risk; the independent re-judging sample reduces but does not eliminate dependence on automated rubrics.
  - Evidence: [b00447-b3f1358934] “Gemini-3.8-Flash gives both BRS and PRS, so part of their agreement could come from the shared model.”; [b00447-b3f1358934] “We also re-judged a stratified sample of 418 probes with Claude Sonnet 5”
- The benchmark requires explicit setting selection and a wrapper because ordinary runtimes do not implement many preferences as native controls; measured performance may therefore differ from unwrapped deployed agents.
  - Evidence: [b00057-d0fd8ade8e] “Current LLM agent runtimes do not support many interaction preferences as executable controls”; [b00057-d0fd8ade8e] “MemPABench therefore has the PA state its choice explicitly.”
- Model-contract failures are assigned worst scores and remain in denominators, so condition results conflate preference competence with runtime/tool-protocol reliability.
  - Evidence: [b00387-12539caed7] “For a probe with a model-capability failure, we assign PSA=0 and BRS=1 without reducing the denominator”; [b00387-12539caed7] “Of the 70 floored probes (67 final, 3 pre), 64 failed in every run.”

## Reproducibility

**Status:** partial

The protocol is unusually detailed and claims released code, prompts, environment, and data, supporting a partial rating. Strong reproducibility cannot be assigned from the supplied document alone because immutable versions, environment capture, and independent reproduction evidence are absent.

**Available artifacts**

- The paper states that the environment and data are released.
- The paper states that full prompts are released with the code.
- The document specifies model names, memory-system versions, temperatures, token limits, retrieval limits, probe repetition, aggregation, failure handling, and bootstrap procedure.

**Missing pieces**

- The supplied blocks do not provide a repository URL, commit hash, immutable artifact version, license, dependency lockfile, hardware specification, cost accounting, or executable reproduction log.
- Exact provider-side model snapshots are not consistently immutable; one model name is described as mapping to a particular checkpoint during the authors’ runs.
- The supplied evidence does not demonstrate an independent end-to-end reproduction of the reported tables.

## AIDB assessment

- Novelty: High benchmark novelty: the paper combines on-policy persistent histories, executable tasks, contextual isolation, controlled preference change, explicit selection, and behavioral realization for interaction preferences rather than factual or content memory.
- Usefulness: High diagnostic usefulness for agent-memory research. The acquisition–selection–realization decomposition, No Memory and Oracle controls, and context/change probes reveal distinct failure modes. Direct product conclusions should wait for validation with real users and natural deployments.
- Confidence: medium
- Recommended action: read
- Rationale: The controlled evidence convincingly shows that generic retrieval memory is insufficient in this environment and that file consolidation trades temporal adaptation for contextual spillover. The benchmark design merits close study, but simulated users, judgment-heavy targets, automated scoring, and wrapper-mediated behavior limit immediate adoption as a definitive product benchmark.

## Uncertainties

- **It is unresolved whether results generalize from four scripted persona worlds to real users who express preferences inconsistently, implicitly, or strategically.** — The benchmark may overestimate learnability because every accumulation session guarantees a preference-bearing reaction, or underestimate it if real users provide clearer direct corrections.
  - Evidence: [b00341-35741b07e5] “The reception side leaves no room for silent acceptance.”; [b00342-393c5176f0] “Every accumulation session reaches this reaction.”
- **The causal attribution of retrieval failure versus extraction or storage failure is broad for Simple RAG but demonstrated for Mem0 and MemOS through a small selected case study.** — System redesign differs depending on whether failures arise in writing, indexing, querying, ranking, or policy use.
  - Evidence: [b00098-6359781118] “we conducted a case study on the stores of all three retrieval-based conditions for two final probes of User B”
- **The effect of memory-side model choice is not isolated: File memory, Mem0, and MemOS use different consolidation or memory models and representations.** — Observed system differences cannot be attributed solely to file versus retrieval architecture without factorial controls.
  - Evidence: [b00083-38a5e564de] “File memory, nanobot’s built-in memory, uses DeepSeek-V4-Flash”; [b00083-38a5e564de] “uses GPT-5.5 as its memory LLM”

## Open questions

- Would the ranking persist with real users, silent acceptance, contradictory feedback, and preferences not guaranteed to surface in every session?
- Can context-tagged retrieval improve CS without sacrificing File memory’s PET gain?
- How much performance is determined by memory representation, retrieval query, memory-side model, backbone prior, or wrapper compliance?
- Would human evaluation reproduce BRS and PRS rankings, especially for difficult settings and consequential outward actions?
- Can a policy trained specifically to obey interaction controls close the Oracle selection-to-realization gap?

## Proposed AIDB experiments

- **Hypothesis:** A structured preference store keyed by user, context, attribute, validity interval, and evidence provenance will retain File memory’s temporal benefit while reducing cross-context carry-over.
  - Baseline: File memory using its existing consolidated Markdown representation, under the same users, backbones, sessions, and probe repeats.
  - Primary metric: Joint objective: PET must be no lower than the File-memory baseline while CS increases and carry-over decreases, using the same cluster-bootstrap analysis.
  - Stop condition: Stop if the confidence interval for the PET difference crosses the predeclared non-inferiority margin or if neither CS nor carry-over improves clearly over File memory.
- **Hypothesis:** Attribute-aware retrieval queries and reranking will retrieve interaction-preference evidence more often than user-message-only vector search and improve PSA.
  - Baseline: Simple RAG with the paper’s existing user-message query, embedding model, retrieval depth, and prompt budget.
  - Primary metric: Applicable-preference retrieval rate in blinded input audits, with PSA as the confirmatory behavioral metric.
  - Stop condition: Stop if retrieval incidence does not improve after a predeclared probe sample, or if higher retrieval incidence fails to produce a positive PSA difference without worsening CS.
- **Hypothesis:** A policy-level compliance intervention trained or prompted against default over-explanation and unsafe inference will improve realization even when selection is already correct.
  - Baseline: The existing Oracle condition with the same wrapper and target-setting input.
  - Primary metric: Pass rate at BRS of 4 or higher on the five difficult settings, supplemented by model-contract failure rate.
  - Stop condition: Stop if the pass-rate interval does not improve over Oracle or if gains come with a higher contract-failure rate or lower task completion.
